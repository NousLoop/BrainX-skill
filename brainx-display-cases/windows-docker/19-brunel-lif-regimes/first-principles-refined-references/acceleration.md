# Execution and parity evidence

The network stores 15,625,000 edges as two source-row CSR graphs with scalar one weights. BrainEvent visits active presynaptic events; there is no dense NxN product. Native BrainPy-State voltage/delta-input dynamics and a BrainState Delay remain in the compiled Module graph. Every rollout is one state-aware jit(for_loop), with packed binary spike observation and no host timestep dispatch or voltage history. Static graph and shape are reused for the four conditions within each seed/grid group; g and eta are runtime inputs.

The focused small reference checks give identical spikes and maximum absolute voltage errors below 0.00003 mV at both grids. Exact full-size rerun parity includes packed spikes, per-bin E/I counts and final voltage. See checks/components.json and checks/acceleration.json. The representative 500-step full-size run takes 2.98 s cold and 1.73 s warm; these are synchronized timings, not a claimed speedup against another scientific implementation. No lower-precision or approximate event optimization is used.

Production enumerates independent runs in separate processes: three baseline seed groups on disjoint thirds of the available CPU set, then the seed101 fine-grid group. Each process owns its RNG, dynamical State, graph object and distinct artifact names. This limits concurrent packed history/compiler memory in the ~7-GB container and uses CPU cores without introducing shared RNG or State. It is process concurrency, not stateful vmap. The per-process physics is identical to the single-process benchmark; checks/worker_affinity_parity.json records exact output parity under the production affinity. No transform is added solely to construct conditions. Source graph construction and host statistics/serialization remain outside compilation.

The only pre-production implementation change after the first replay attempt was stable State restoration (documented in brainx-study-record.md). Failed check logs are preserved. Frozen scientific choices did not change. The container is Linux running over a Windows-mounted filesystem (df reports C:); package/device provenance is preserved rather than assuming a native Windows installation.
